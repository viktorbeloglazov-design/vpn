# Как работают маршруты

Приложение управляет таблицей маршрутизации macOS: решение принимается по
**адресу назначения**. Ниже — что именно делает служба в каждом режиме.

## Весь трафик через VPN

`AllowedIPs = 0.0.0.0/0` и маршрут по умолчанию уходит в интерфейс WireGuard.
Отдельным маршрутом сохраняется путь до самого VPN-сервера через физический шлюз,
иначе туннель «отрезал бы сам себя». DNS переключается на серверы из конфига.

Это самый предсказуемый режим: из Казахстана вас видят все сайты.

## Только правила через VPN

`AllowedIPs` собирается из ваших правил. Всё остальное идёт напрямую,
системный DNS не трогается — локальная сеть, принтеры и рабочие VPN продолжают
работать как раньше.

Полезно, когда нужен казахстанский IP для пары сервисов, а не для всего.

## Всё через VPN, кроме правил

`AllowedIPs = 0.0.0.0/0`, но для адресов из правил ставятся отдельные маршруты
через физический шлюз (`route add -net <подсеть> <шлюз>`). Более узкий маршрут
выигрывает — такой трафик идёт мимо туннеля.

Рабочая схема для бизнеса: казахстанский IP по умолчанию, а банки РФ, кабинеты
Wildberries/Ozon и китайские площадки — напрямую, чтобы их антифрод не видел
смену страны.

## Правила

**IP / подсеть** — точный и надёжный вариант: `92.46.0.0/16`, `5.35.96.12`.
Одиночный адрес автоматически превращается в `/32`.

**Домен** — служба резолвит его в IP и ставит маршруты на полученные адреса.
Для доменов второго уровня дополнительно резолвится `www.`-вариант.
Пересчёт идёт каждые `N` минут (по умолчанию 5, настраивается) и при каждом
изменении списка правил.

### Ограничения доменных правил

- **CDN.** Крупные сайты (Cloudflare, Akamai) отдают разным клиентам разные
  адреса и делят их с тысячами других сайтов. Маршрут на такой IP затронет и
  «соседей». Для критичных случаев лучше указывать подсети провайдера.
- **Поддомены.** Правило `ozon.ru` не покрывает автоматически `api.ozon.ru`,
  если у них разные адреса. Добавляйте нужные поддомены отдельными правилами.
- **Смена адресов.** Между пересчётами адрес может смениться — тогда соединение
  пойдёт «не туда» до следующего обновления. Уменьшите интервал, если это мешает.
- **DNS.** В режимах «весь трафик» и «всё кроме правил» DNS-запросы уходят через
  туннель, поэтому ответы будут казахстанскими — это нормально, маршрутизация
  всё равно выполняется по IP.

## Что маршрутами сделать нельзя

- Разделить трафик по приложениям («Safari через VPN, Telegram напрямую») —
  для этого нужен системный расширитель NetworkExtension с платным аккаунтом
  разработчика Apple.
- Разделить по URL или по домену внутри одного IP-адреса.

## Диагностика

```bash
netstat -rn -f inet | head -30          # таблица маршрутов
route -n get ozon.ru                    # каким путём пойдёт запрос
sudo wg show                            # состояние туннеля, handshake, трафик
tail -f /var/log/kztunnel.log           # что делает служба
```

Если в выводе `route -n get` интерфейс `utunN` — трафик идёт через VPN,
если `en0`/`en1` — напрямую.
