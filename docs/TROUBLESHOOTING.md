# Если что-то пошло не так

Начните с автоматической проверки — она за несколько секунд покажет,
что установлено, работает ли служба и каким путём идёт трафик:

```bash
sudo ./scripts/doctor.sh
```

## «Служба не установлена» / «Служба не отвечает»

```bash
sudo ./scripts/install.sh
sudo launchctl print system/com.kztunnel.helper | head -20
tail -20 /var/log/kztunnel.log
```

Частая причина — не установлены зависимости: `brew install wireguard-tools wireguard-go`.

## Кнопка включается, но статус «Подключение…» не меняется

Значит нет handshake с сервером. Проверьте по очереди:

```bash
# 1. Доступен ли сервер вообще
ping -c 3 ВАШ_IP_СЕРВЕРА

# 2. Открыт ли UDP-порт (на сервере)
ss -lunp | grep 51820

# 3. Состояние туннеля на Mac
sudo wg show
```

- нет ответа от порта → закрыт UDP в firewall хостера или в `ufw`;
- `latest handshake` пуст → неверный публичный ключ сервера или preshared-ключ;
- handshake есть, но интернета нет → на сервере не включён форвардинг или NAT
  (перезапустите `install-wg-kz.sh`).

## VPN включён, но сайты видят не Казахстан

1. Нажмите «Проверить мой IP» в приложении.
2. Если показывает страну сервера — всё в порядке, а сайт определяет регион по
   другим признакам (язык системы, аккаунт, платёжная карта, часовой пояс).
3. Если показывает вашего провайдера — проверьте режим на вкладке «Маршруты»:
   в режиме «только правила» через VPN идут лишь перечисленные адреса.
4. Проверьте утечку IPv6: включите «Отключать IPv6, пока VPN включён».
5. Проверьте DNS: `scutil --dns | head -20`.

## Часть сайтов перестала открываться при включённом VPN

Обычно это банки и госсервисы, которые не любят зарубежный IP. Переключитесь в
режим «Всё через VPN, кроме правил» и добавьте наборы «Банки и госуслуги РФ» и
«Маркетплейсы РФ».

## Медленно работает или рвутся большие загрузки

Уменьшите MTU на вкладке «Сервер»: 1420 → 1380 → 1280. Это типичное лекарство,
когда канал до сервера идёт через несколько операторов.

## После выключения VPN пропал интернет

```bash
sudo wg-quick down /var/run/kztunnel/kz0.conf
sudo launchctl kickstart -k system/com.kztunnel.helper
networksetup -setv6automatic Wi-Fi
```

Служба возвращает DNS и IPv6 сама, но если её убили принудительно (`kill -9`),
эти команды приводят систему в исходное состояние.

## Не сохраняются настройки

Приложение пишет в `/Library/Application Support/KZTunnel/config.json`.
Права должны быть такими:

```bash
ls -ld "/Library/Application Support/KZTunnel"
# drwxrwx---  root  staff
```

Если это не так: `sudo ./scripts/install.sh` восстановит права.

## Полный сброс

```bash
sudo ./scripts/uninstall.sh --purge
./scripts/build.sh
sudo ./scripts/install.sh
```

## Туннель включён, а интернета нет

Самая частая причина — сервер не знает ключ этого клиента. В конфиге
`AllowedIPs = 0.0.0.0/0`, поэтому весь трафик уходит в туннель сразу, а сервер
незнакомому пиру не отвечает: связи нет вообще. Признак однозначный — нет
рукопожатия и ноль принятых байт:

```bash
wg show            # нет строки latest handshake, transfer: 0 B received
```

Лечится добавлением `[Peer]` клиента в `/etc/wireguard/wg0.conf` на сервере:

```bash
wg syncconf wg0 <(wg-quick strip wg0)
```

Если рукопожатие есть, а сайты не открываются — смотрите MTU (попробуйте 1380)
и NAT на сервере.

## Проверить, что выход действительно казахстанский

```bash
sudo bash scripts/test-configs-kz.sh clients/*.conf
sudo bash scripts/test-configs-kz.sh --country KZ mac.conf
```

Скрипт по очереди поднимает каждый конфиг, ждёт рукопожатие и печатает внешний
IP со страной; ожидаемый код страны — `KZ`. Если рукопожатия нет, он прямо
скажет, что пир не добавлен на сервер. Вручную то же самое: включить туннель и
открыть `https://ifconfig.co/json` — в поле `country_iso` должно быть `KZ`.
На время проверки весь трафик машины идёт в туннель, возможны короткие разрывы.

## Рукопожатие проходит, данные не идут — провайдер режет WireGuard

Самый коварный случай. Признаки: туннель показывает «подключён», есть свежее
рукопожатие, счётчик отправленных байт растёт, а принято ровно 92 байта — это
ответ на рукопожатие и больше ничего. Сайты не открываются.

Проверять на сервере нечего: `doctor-server.sh` показывает всё зелёным,
форвардинг включён, NAT считает пакеты, `curl --interface 10.8.0.1` возвращает
нужную страну. Сервер исправен.

Причина — фильтрация по сигнатуре протокола у интернет-провайдера. Рукопожатие
пропускают (один короткий пакет), а пакеты данных опознают и молча отбрасывают.
Признак, подтверждающий версию: через мобильный интернет то же подключение
работает, а через домашний или офисный Wi-Fi нет, либо наоборот — операторы
обновляют фильтры вразнобой.

Что **не** помогает, проверено: смена порта (51820, 443, высокий случайный),
MTU на клиенте, MTU на сервере, приведение конфига к виду рабочего стороннего
сервиса. Блокируют не порт и не размер пакетов, а сам протокол.

Помогает только маскировка трафика — **AmneziaWG**: тот же WireGuard по скорости,
но с мусорными вставками и случайными заголовками, по которым фильтр не может
опознать туннель. Ставится поверх существующего сервера приложением AmneziaVPN
(`amnezia.org`): «VPN на своём сервере» → данные SSH → протокол **AmneziaWG**
(не обычный WireGuard, названия в списке похожи). Существующая настройка
WireGuard при этом остаётся нетронутой.

Стоит иметь в виду для KZTunnel: приложение работает на обычном WireGuard,
поэтому в сетях с такой фильтрацией оно столкнётся с тем же самым.
