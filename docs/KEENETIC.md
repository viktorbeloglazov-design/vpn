# Keenetic Sprinter: один ключ WireGuard на всю домашнюю сеть

Задача: есть один клиентский конфиг WireGuard (`*.conf`), а пользоваться им
должны все устройства — телефоны, ноутбуки, телевизор, приставка.

## Почему ключ нельзя просто скопировать на каждое устройство

В WireGuard пара ключей — это и есть личность устройства. Сервер держит для
каждого публичного ключа один текущий адрес источника (endpoint) и один
IP в туннеле. Если тем же ключом подключиться с телефона, а потом с ноутбука,
сервер запомнит последний handshake и отправит обратный трафик только туда —
второе устройство останется без ответов. Дальше устройства начинают по кругу
перебивать друг друга: связь рвётся у обоих. Копия ключа работает, только пока
устройство ровно одно и включено в один момент времени.

Правильных выходов два:

1. **Туннель на роутере.** Ключ живёт в одном месте — на Keenetic. Для сервера
   это по-прежнему одно устройство, а дома через него выходит вся сеть.
   Ничего не нужно настраивать на телефонах и телевизоре.
2. **Отдельный ключ на каждое устройство.** Нужен доступ к серверу: там
   добавляется новый пир (в этом репозитории — `server/add-client.sh`). Если
   конфиг выдал сторонний сервис, второй ключ можно только попросить у него.

Ниже — первый вариант, он же и решает исходную задачу «чтобы работало на всех».

## Что понадобится

- Keenetic Sprinter (KN-3710) с KeeneticOS 4.x — WireGuard поддерживается;
- сам файл конфига (`[Interface]` с `PrivateKey` и `[Peer]` с `Endpoint`);
- доступ в веб-интерфейс роутера (`my.keenetic.net` или `192.168.1.1`).

## Шаг 1. Компоненты

**Управление → Общие настройки → Изменить набор компонентов** — отметьте:

- «WireGuard VPN» — сам протокол;
- «Приоритеты подключений» — понадобится, если через туннель должны идти
  не все устройства, а выбранные.

Роутер перезагрузится сам.

## Шаг 2. Подключение

**Интернет → Другие подключения → WireGuard → Добавить подключение.**

В KeeneticOS 4.x есть кнопка «Загрузить из файла» — она принимает `.conf`
целиком. Если её нет, поля заполняются вручную:

| Строка конфига | Поле в Keenetic |
|---|---|
| `PrivateKey` (раздел `[Interface]`) | Приватный ключ |
| `Address = 10.74.7.26/24` | Адрес и маска подсети туннеля |
| `DNS = 1.1.1.1, 8.8.8.8` | здесь не задаётся — см. шаг 5 |
| `PublicKey` (раздел `[Peer]`) | Публичный ключ пира |
| `PresharedKey` | Preshared key |
| `Endpoint = 91.200.148.112:29152` | Адрес и порт сервера |
| `AllowedIPs = 0.0.0.0/0` | Разрешённые подсети пира |
| `PersistentKeepalive = 30` | Проверка активности, 30 с |

`AllowedIPs = 0.0.0.0/0` означает «весь трафик в туннель» — так и нужно,
если цель в том, чтобы сайты видели IP сервера.

Готовый к загрузке файл и те же настройки в виде команд делает скрипт:

```bash
./scripts/keenetic-wg.sh ~/Downloads/KotiKey.conf --out ~/keenetic --name KotiKey
```

Он выдаёт `keenetic-<имя>.conf` (для кнопки «Загрузить из файла») и
`keenetic-<имя>.cli.txt` — блок для **Управление → Общие настройки →
Командная строка**, если импорт файла недоступен:

```
interface Wireguard0
    description "KotiKey"
    security-level public
    ip address 10.74.7.26 255.255.255.0
    ip mtu 1420
    ip tcp adjust-mss pmtu
    ip global 4
    wireguard private-key <приватный ключ>
    wireguard peer <публичный ключ сервера>
        endpoint 91.200.148.112:29152
        preshared-key <preshared key>
        keepalive-interval 30
        allow-ips 0.0.0.0 0
        exit
    up
    exit
system configuration save
```

`security-level public` включает NAT на туннеле — без него у домашних устройств
будет handshake, но не будет интернета. `ip global` делает подключение
интернет-каналом (в веб-интерфейсе это галка «Использовать для выхода
в Интернет»).

## Шаг 3. Туннель как выход в интернет

В карточке подключения включите **«Использовать для выхода в Интернет»**.
После этого WireGuard появляется в списке приоритетов подключений наравне
с кабелем провайдера и мобильным модемом.

## Шаг 4. Кто ходит через VPN

**Всем устройствам сразу:** «Интернет → Приоритеты подключений» — перетащите
WireGuard на первое место, выше провайдера. Вся сеть выходит через туннель;
если туннель упадёт, роутер вернётся на провайдера.

**Выборочно:** «Мои сети и Wi-Fi → Приоритеты подключений» — создайте профиль
(например, «Через VPN»), поставьте в нём WireGuard первым, а провайдера —
резервом. Затем в «Список устройств» назначьте профиль нужным устройствам.
Телевизор — через VPN, рабочий ноутбук — напрямую; при этом ключ по-прежнему
один.

Устройство должно быть зарегистрировано в списке — незарегистрированные идут
по общему профилю.

## Шаг 5. DNS

Keenetic не берёт строку `DNS` из конфига: имена сайтов продолжит резолвить
провайдер, и по запросам будет видно, куда вы ходите, даже когда сам трафик
в туннеле.

**Интернет → Список DNS-серверов** — удалите полученные от провайдера
и добавьте `1.1.1.1` и `8.8.8.8`. Надёжнее — там же добавить DNS-over-TLS
(`one.one.one.one`, `1.1.1.1:853`): тогда провайдер не видит и самих запросов.

## Шаг 6. Проверка

- В карточке подключения — «Подключено» и свежий handshake (секунды, не часы).
- На любом домашнем устройстве откройте `2ip.ru` или `whoer.net`: должен
  показываться IP сервера, а не провайдера.
- Проверьте с телефона по Wi-Fi и с телевизора — IP должен быть один и тот же.

## Свой сервер вместо чужого

Чужой конфиг (как `KotiKey`) — это доверие к владельцу сервера: он видит, куда
вы ходите, и может выключить ключ. Свой сервер снимает оба вопроса.

**Бесплатно и всерьёз — Oracle Cloud Always Free.** Даёт бессрочно бесплатную
машину (ARM Ampere до 4 ядер / 24 ГБ либо два маленьких AMD) и 10 ТБ
исходящего трафика в месяц — для VPN это очень много. Регионы: Франкфурт,
Амстердам, Цюрих, Лондон, Сингапур и др. Оговорки честные:

- нужна банковская карта для верификации (холд около $1), из России
  регистрация проходит не всегда — иногда помогает карта другого банка;
- простаивающие бесплатные ARM-машины Oracle имеет право забрать; на
  аккаунте, переведённом в платный (Pay As You Go), этого не делают, а
  бесплатная квота продолжает действовать;
- мощностей ARM в популярных регионах часто нет — берут с нескольких попыток.

Остальные «бесплатные» варианты хуже: у Google Cloud на бесплатной машине
всего 1 ГБ исходящего трафика в месяц (для VPN бессмысленно), у AWS бесплатно
только первые 12 месяцев. Бесплатные VPN-сервисы не рассматриваем: чужой
сервер плюс неизвестно чья бухгалтерия на ваших данных.

Если нужна предсказуемость, а не экономия: VPS за 200–400 ₽/мес у любого
европейского хостера надёжнее бесплатных квот — никто не заберёт машину,
пока вы платите.

**Установка** — скриптом из этого репозитория, на чистой Ubuntu 22.04/24.04:

```bash
scp server/install-wg-kz.sh root@ВАШ_СЕРВЕР:/root/
ssh root@ВАШ_СЕРВЕР 'bash /root/install-wg-kz.sh --client keenetic'
```

Скрипт поднимает WireGuard и печатает готовый клиентский конфиг. Его —
в `scripts/keenetic-wg.sh`, дальше по шагам выше. Ещё ключи (телефон, ноутбук
в поездке) добавляются на сервере через `server/add-client.sh <имя>`: у каждого
устройства свой ключ, и они не мешают друг другу.

**Про надёжность.** Свой сервер — постоянный IP, который вы контролируете:
для антифрода банков и кабинетов маркетплейсов это скорее плюс, чем
прыгающие адреса коммерческих VPN. Минус тот же самый: адрес датацентровый,
и часть стриминговых сервисов такие адреса не любит.

**Если туннель не поднимается у конкретного провайдера.** Часть российских
операторов режет UDP-трафик WireGuard. Первое, что стоит попробовать, —
поднять сервер на порту 443/UDP вместо 51820
(`install-wg-kz.sh --port 443 --client keenetic`). Если и это не помогает, нужна обфускация
(AmneziaWG, Xray/VLESS-Reality) — её поддержка требуется на обеих сторонах;
штатная прошивка Keenetic умеет WireGuard, IKEv2/IPsec, OpenVPN и SSTP,
а под обфускацию на роутере понадобится Entware (см. ниже).

## Только нужные сервисы через VPN

Именно так и стоит работать: основной канал — провайдерский, в туннель уходит
только то, что нужно. Меньше нагрузка на туннель, банки и маркетплейсы видят
привычный российский IP, а скорость обычных сайтов не режется.

Сразу о главном ограничении: **роутер не умеет делить трафик по программам**.
Решение принимается по адресу назначения (и по устройству-источнику) — роутер
не видит, какая программа на ноутбуке открыла соединение. Поэтому «только
нужные программы» на практике делается одним из трёх способов.

### 1. По адресам назначения — основной способ

Туннель поднят, но **не** назначен основным выходом в интернет. Для нужных
сайтов добавляются отдельные маршруты через интерфейс WireGuard: более узкий
маршрут выигрывает у маршрута по умолчанию, поэтому в туннель уходит только
этот трафик.

Порядок:

1. Создайте подключение WireGuard, как описано выше, но в общем списке
   приоритетов **не** поднимайте его наверх (галка «Использовать для выхода
   в Интернет» может остаться — важно, что провайдер стоит первым).
2. **Сетевые правила → Маршрутизация → Добавить маршрут**: тип «Маршрут до
   узла» или «до сети», адрес назначения, интерфейс — ваше подключение
   WireGuard. В KeeneticOS 4.x поле адреса принимает и доменное имя — роутер
   сам следит за его адресами; если в вашей версии прошивки поля для домена
   нет, добавляйте IP-адреса.
3. Проверьте: `2ip.ru` показывает провайдерский IP, а нужный сервис —
   открывается и считает вас иностранцем.

Списком адресов удобно не заниматься руками:

```bash
./scripts/keenetic-routes.sh --set ai --set social
./scripts/keenetic-routes.sh --set ai --out ~/keenetic/routes.txt
./scripts/keenetic-routes.sh --list          # что входит в наборы
```

Скрипт резолвит домены и выдаёт готовые команды `ip route ... Wireguard0 auto`
для командной строки роутера, плюс `--remove` — команды на снятие.

Что важно понимать про этот способ:

- **Адреса меняются.** Сайты за Cloudflare/Akamai живут на общих и плавающих
  адресах: список надо пересобирать (раз в месяц-два, либо когда сервис
  перестал открываться), а маршрут на такой IP заодно задевает соседей по
  тому же адресу. Где есть вариант с доменным маршрутом в прошивке — берите
  его, там роутер обновляет адреса сам.
- **DNS остаётся провайдерским.** Имя резолвится напрямую, в туннель уходит
  только соединение. Обычно это то, что нужно; если сервис не открывается
  из-за подмены DNS, включите на роутере DNS-over-TLS (`1.1.1.1:853`).
- **Тяжёлые сервисы вроде YouTube** по такому списку ведут себя плохо: у них
  сотни CDN-адресов, которые меняются на ходу. Для них проще держать отдельное
  устройство или профиль (пункт 2), а не список маршрутов.

### 2. По устройствам — когда «нужное» живёт на отдельном устройстве

**Мои сети и Wi-Fi → Приоритеты подключений**: профиль, где WireGuard стоит
первым, и в него — конкретные устройства. Телевизор целиком через туннель,
рабочий ноутбук — напрямую. Грубее, чем по адресам, зато настраивается за
минуту и ничего не ломается при смене IP у сайтов.

Удобная комбинация: рабочий ноутбук и телефоны — в обычном профиле (всё
напрямую), а приставка или второй телефон — в VPN-профиле.

### 3. По программам — что реально возможно

- **Android.** Официальное приложение WireGuard умеет «Применять к
  приложениям»: выбираете, какие программы идут в туннель, остальные — мимо.
  Это настоящий режим «по программам», бесплатно и без роутера.
- **Программы со своим полем прокси** (Telegram, браузеры, торрент-клиенты,
  многие разработческие инструменты). На роутере поднимается SOCKS5-прокси,
  выходящий через туннель, а в программе указывается `192.168.1.1:1080`.
  Тогда через VPN идёт ровно эта программа, а система в целом — напрямую.
  Требуется Entware: USB-накопитель в роутер, **Приложения → OPKG**, затем
  пакет `3proxy` или `microsocks`. Способ рабочий, но это уже администрирование
  роутера, а не пара галок.
- **Windows и macOS.** Штатный WireGuard делит трафик только по адресам
  (`AllowedIPs`) — ровно это и делает приложение из этого репозитория
  (`KZTunnel`, режимы «только правила» и «всё, кроме правил»). Деление по
  программам на Windows требует сторонних инструментов вроде Proxifier
  (платный), на macOS — платного аккаунта разработчика Apple и системного
  расширения.

Практический вывод: 90 % задач закрывается первым способом (маршруты на
нужные домены), оставшееся — вторым; третий нужен, когда программа и сайт
делят один адрес с чем-то, что через VPN пускать нельзя.

## Устройства вне дома

Когда телефон уходит в мобильную сеть, дома его уже нет — туннель роутера ему
не помогает. Варианты:

1. **Второй ключ у поставщика VPN** — самый простой путь, если его дают.
2. **VPN-сервер на самом Keenetic.** Телефон подключается к роутеру, а роутер
   уводит его трафик в тот же туннель. Работает только при белом (публичном)
   IP у роутера: KeenDNS в облачном режиме проксирует HTTP(S), но не WireGuard.
   Белый IP обычно даёт провайдер за небольшую плату.

Заготовку для второго варианта делает тот же скрипт:

```bash
./scripts/keenetic-wg.sh ~/Downloads/KotiKey.conf --out ~/keenetic \
    --endpoint ВАШ_БЕЛЫЙ_IP --server-peer iphone --server-peer macbook
```

Он выпускает ключи, пишет `keenetic-server.cli.txt` для роутера (интерфейс
`Wireguard1`, порт 51820) и по файлу `peer-<имя>.conf` на каждое устройство —
их можно импортировать в приложение WireGuard или показать QR-кодом
(`qrencode -t ansiutf8 < peer-iphone.conf`). В Keenetic не забудьте открыть
UDP-порт 51820 и добавить `Wireguard1` в тот же профиль приоритетов, где
первым стоит `Wireguard0`.

## Если что-то не работает

**Handshake проходит, интернета у устройств нет.** Не включён NAT на туннеле:
`security-level public` (веб-интерфейс: подключение должно быть именно
интернет-подключением, а не просто интерфейсом).

**Сайты открываются наполовину, видео зависает.** Великоват MTU. Снизьте
1420 → 1380 → 1280 (`ip mtu 1380`), `ip tcp adjust-mss pmtu` должен быть
включён. Особенно актуально, если провайдер даёт интернет по PPPoE.

**Подключение отваливается через несколько минут.** `PersistentKeepalive`
должен быть 25–30 с — иначе NAT провайдера закрывает UDP-сессию.

**Не совпадают подсети.** Если домашняя сеть роутера случайно окажется
в той же подсети, что и адрес туннеля (здесь — `10.74.7.0/24`), маршруты
столкнутся. Домашнюю сеть в этом случае переведите, например, на
`192.168.31.0/24`.

**Скорость ниже, чем у провайдера.** WireGuard на Keenetic считается
процессором роутера, аппаратного ускорения для него нет. Посмотрите загрузку
CPU в системном мониторе под нагрузкой: если она в потолке, это предел модели,
а не настроек.

**Тот же ключ остался на телефоне.** Выключите там WireGuard совсем — иначе
телефон и роутер будут перебивать друг друга ровно так, как описано в начале.

## Про сам файл конфига

`PrivateKey` и `PresharedKey` — это доступ к вашему VPN. Не выкладывайте конфиг
в чаты и не коммитьте в репозиторий: любой, у кого он есть, подключится вашим
ключом (и заодно выбьет вас). Если конфиг где-то засветился — просите новый.
