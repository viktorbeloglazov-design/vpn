### Добавлена проверка: номер внутри сборки против номера рядом

Приложения обновляются сами: читают файл вида `android-version.txt`
и сравнивают с собственным номером. Если номер рядом со сборкой
окажется новее, чем внутри неё, обновление пойдёт по кругу —
программа скачает шестьдесят мегабайт, поставит их, снова увидит
себя старой и снова начнёт качать. На Mac это уже случалось: в
`release.yml` с тех пор стоит проверка при сборке.

Но проверка при сборке говорит только про момент сборки. Файлы
выкладываются по одному, и разойтись они могут при выкладке: номер
обновился, а сама сборка не перезалилась. Теперь сверяется то, что
человек скачивает: версия из APK, из `Info.plist` в образе Mac
и из имени папки в архиве Windows — против файлов с номерами.

Сегодня все три сходятся: Android 2.11.0, Mac 3.3.0, Windows 3.3.0.
Проверено и с обратной стороны — на подложенном номере 9.9.9
проверка называет все три расхождения.

### Заодно закрыта та же дыра, что вчера

Вчерашняя правка учила отчёт не называть проверенным то, что не
проверялось. Новые проверки завели её снова: когда проверить
не удавалось — нет `7z` для образа Mac, не читается страница
выпуска, — они возвращали успех, и отчёт писал «в порядке».

Теперь «не смогла проверить» — отдельный ответ, не успех: отчёт
показывает его строкой «пропущена — <причина>», и итог считает
такие проверки непройденными. Переведены все четыре: версии внутри
сборок, прогоны платформ, описание выпуска, выложенная инструкция.

## Выпущено позже в тот же день

### Mac 3.4.0 — служба поднимается сама

Жалоба: каждые 5–15 минут связь пропадает, помогает только
«переустановить службу» руками.

Причина. Служба раз в секунду сверяет состояние сети и для этого
спрашивает систему: `wg`, `networksetup`, `route`, имена у DNS.
Любой такой вопрос может остаться без ответа — система занята, сеть
переключается, DNS молчит. Тогда цикл встаёт: туннель не
поддерживается, состояние не публикуется, связи нет. А для launchd
всё в порядке — процесс жив, перезапускать нечего. Сам себя цикл
не вытащит: он и есть то, что зависло. Оставался только человек
с кнопкой.

Что сделано:

- за службой следит отдельный поток. Полторы минуты без признаков
  жизни — он называет в журнале виновника и завершает службу;
  launchd поднимает её через пять секунд, без пароля и без человека;
- признак жизни — законченное дело, а не пройденный круг. Иначе
  сторож убивал бы службу посреди честного подъёма туннеля, который
  в плохой сети занимает минуты, — вышла бы ровно та поломка,
  от которой он поставлен. Команде отпущено не больше минуты,
  заведомо меньше, чем ждёт сторож;
- запрос имени у DNS шёл без срока: когда DNS не отвечает,
  системный вызов возвращается через полминуты и всё это время
  служба стоит. Теперь ждём пять секунд;
- `wg` запускался дважды в секунду — оставлен один раз за круг;
- одна неудачная попытка опросить туннель считалась поломкой,
  и туннель пересоздавался целиком: минута без связи из-за
  пропущенного ответа. Теперь терпим три осечки подряд.

Причины перезапусков служба записывает рядом с настройками,
а приложение показывает их в отчёте диагностики: следующий разговор
пойдёт по фактам, а не по догадкам.

Выпущено: Mac 3.4.0. Проверено — по постоянной ссылке лежит 3.4.0,
и внутри образа тот же номер. Приложение обновится само; службу
оно предложит обновить один раз с паролем.

В инструкцию добавлена строка: связь пропала на полминуты
и вернулась — это служба перезапустилась сама, переустанавливать
её не нужно.
